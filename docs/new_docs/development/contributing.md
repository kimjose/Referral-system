# Contributing Guide

Thank you for your interest in contributing to the Angaza Referral System! This guide provides information about how you can contribute to the project.

## Code of Conduct

### Our Pledge
We are committed to making participation in this project a harassment-free experience for everyone, regardless of level of experience, gender, gender identity and expression, sexual orientation, disability, personal appearance, body size, race, ethnicity, age, religion, or nationality.

### Our Standards
Examples of behavior that contributes to a positive environment include:
- Using welcoming and inclusive language
- Being respectful of differing viewpoints and experiences
- Gracefully accepting constructive criticism
- Focusing on what is best for the community
- Showing empathy towards other community members

## How to Contribute

### 1. Reporting Bugs
- Use the GitHub issue tracker
- Include detailed steps to reproduce
- Provide expected and actual behavior
- Include screenshots if applicable
- Specify your environment details

### 2. Suggesting Features
- Use the GitHub issue tracker
- Provide a clear description
- Explain the use case
- Include mockups if applicable
- Label as "enhancement"

### 3. Pull Requests
1. Fork the repository
2. Create a new branch
3. Make your changes
4. Run tests
5. Submit a pull request

### 4. Development Process
1. **Setup Development Environment**
   ```bash
   git clone https://github.com/your-org/angaza-referral.git
   cd angaza-referral
   composer install
   npm install
   ```

2. **Create Feature Branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make Changes**
   - Follow coding standards
   - Write tests
   - Update documentation

4. **Commit Changes**
   ```bash
   git add .
   git commit -m "Description of changes"
   ```

5. **Push Changes**
   ```bash
   git push origin feature/your-feature-name
   ```

### 5. Code Standards

#### PHP Code Style
- Follow PSR-12 standards
- Use type hints
- Write PHPDoc blocks
- Keep methods small and focused

#### JavaScript Code Style
- Follow ESLint configuration
- Use ES6+ features
- Write JSDoc comments
- Follow component patterns

#### Database Standards
- Use migrations
- Follow naming conventions
- Add indexes appropriately
- Document schema changes

### 6. Testing

#### Unit Tests
- Write tests for new features
- Maintain test coverage
- Use PHPUnit for PHP
- Use Jest for JavaScript

#### Integration Tests
- Test API endpoints
- Test database interactions
- Test external services
- Maintain test data

### 7. Documentation

#### Code Documentation
- Document all classes
- Document all methods
- Include examples
- Keep docs up to date

#### User Documentation
- Update user guides
- Add feature documentation
- Update API docs
- Include screenshots

### 8. Review Process

#### Pull Request Review
1. Automated checks must pass
2. Code review required
3. Documentation updated
4. Tests added/updated
5. No merge conflicts

#### Review Guidelines
- Check code style
- Verify functionality
- Review documentation
- Test changes locally
